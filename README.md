# jepra

越境BtoBの **リード収集 → 連絡先発掘 → 多言語アプローチ文面 → 効果測定** を
1本のCLIにまとめたもの。

もともとは「フランスの文房具店に日本の文具を売り込む」ための手作業（Google Maps を
見て、サイトを開いて、メールアドレスを探して、CSVにステータスを書く）を自動化した
ものなので、対象は業種と国を変えれば他の案件にそのまま使える。

```
jepra run --country DE --city Berlin --category gift --limit 100 --out berlin.csv
```

## できること

| 工程 | コマンド | 内容 |
|---|---|---|
| 収集 | `scrape` | OpenStreetMap / Google Places から店舗を取得（国・都市・業種指定） |
| 名寄せ | 自動 | 表記揺れ・チェーン支店を判別して重複を統合 |
| 連絡先発掘 | `enrich` | サイトを巡回してメールアドレスを抽出、無ければフォームURLを記録 |
| 文面生成 | `compose` | FR/EN/JA × A/B の2枝を自動割り当て |
| 記録 | `log` | 送信・バウンス・開封・返信・商談・成約 |
| 追客 | `inbox` / `followup` | 対応待ちの抽出と、反応のないリードへの追客文面生成 |
| 測定 | `stats` | 到達率・返信率・商談化率、都市/業種/文面枝ごとの内訳とA/B検定 |
| 納品 | `export` | 日本語ヘッダのCSV（Excelでそのまま開ける） |

## インストール

```bash
git clone <このリポジトリ>
cd jepra
pip install -e '.[live]'     # 実データ収集をする場合
pip install -e .             # デモと集計だけなら依存ゼロ
```

Python 3.9 以上。`live` の追加依存は `requests` のみ（HTML解析は標準ライブラリ）。

## まず動かす

通信もAPIキーも不要で全工程が流れる。**商談デモはこれを使う**（回線に依存しない）。

```bash
jepra demo
```

第1部で実在するフランスの文房具店81件を収集→連絡先発掘→仏語文面生成まで通し、
第2部で1,200通配信した場合の効果測定（ファネル・都市別・A/B検定）を見せる。
第2部の数値は架空データで、実在の店舗とは無関係。

## 実データで使う

### 1. 差出人情報を用意する

```bash
jepra profile init      # jepra.profile.json の雛形が出る
```

中の `<自社名>` 等を書き換える。ここが未設定だと文面にプレースホルダが残る。

### 2. 収集から文面生成まで

```bash
jepra run --country FR --city Lyon --category stationery \
          --limit 100 --source overpass --out lyon.csv
```

| ソース | APIキー | 費用 | 評価(★) | 備考 |
|---|---|---|---|---|
| `overpass` | 不要 | 無料 | ✗ | OpenStreetMap。網羅性に地域差あり |
| `google` | 要 | 従量 | ✓ | 評価で優先度を付けられる。本番向き |
| `fixture` | 不要 | 無料 | ✓ | 同梱のデモデータ |

Google を使う場合は Places API (New) を有効化して `GOOGLE_MAPS_API_KEY` を設定する。

まず `overpass` で無料に拾い、足りない都市だけ `google` で補うと安い。
同じDBに両方入れても名寄せで統合される。

### 3. 送信して結果を記録する

送信自体はこのツールの範囲外（既存のメールクライアント／配信ツールを使う）。
結果だけ記録すれば集計できる。

```bash
jepra log sent    --lead 42
jepra log replied --lead 42          # 文面枝は直近の送信から自動で引き継ぐ
jepra log meeting --lead 42
```

配信ツールのCSVをまとめて流し込むこともできる。

```bash
jepra import-events results.csv      # 列: リードID/店名, 種別, 日時, 文面枝
```

### 4. 追いかける

返信は放っておくと埋もれ、無反応は忘れられる。どちらも商談数に直結するので、
勘ではなくクエリで拾う。

```bash
jepra inbox                  # 「返信あり・未対応」と「追客推奨」を一覧
jepra followup --days 7      # 初回送信から7日反応がないリードに追客文面を生成
```

追客の文面枝（A/B）は初回送信から引き継ぐ。ここで枝を変えると、返信がどちらの
文面によるものか分からなくなり、A/Bの集計が壊れる。返信・バウンス・配信停止の
あったリードは追客対象から自動で外れる。

### 5. 測る

```bash
jepra stats                  # 全体のファネル
jepra stats --by city        # 都市別
jepra stats --by variant     # 文面 A/B（z検定つき）
jepra stats --json           # 機械可読
```

```
ファネル
  収集した店舗             1200
  メール取得済み            1200  (100.0%)
  送信                 1200
  　うちバウンス              64
  到達                 1136  (94.7%)
  開封                  475  (41.8%)
  返信                   82  (7.2%)
  前向きな返信               44  (53.7%)
  商談化                  15  (1.3%)

文面 A/B（返信率）
  枝 A: 返信率 5.9% (572通中)
  枝 B: 返信率 8.5% (564通中)
  差分: B が A より 2.6pt 高い / p値 0.095 → 傾向あり（p<0.10）。追加送信で確認の余地あり
```

（上は `jepra demo` 第2部の出力＝架空データ）

**到達率 = (送信 − バウンス) / 送信、返信率 = 返信 / 到達。**
返信率の分母を送信ではなく到達にしているのは、届いていない宛先を分母に入れると
文面の良し悪しが測れなくなるため。

### 6. 既存のCSVを取り込む

```bash
jepra import-csv data/legacy/papeterie_nationwide.csv
jepra import-csv data/legacy/paris_papeterie_master.csv --city Paris
```

列名は日本語・英語とも自動判定する（「店名」「店舗名」「Name」など）。
**都市列を持たないCSVには `--city` を必ず付ける** — 都市は名寄せキーの一部なので、
空のままだと同じ店が別レコードとして残る。

## 設計上の判断

**正はSQLite、CSVは入口と出口だけ。** CSVを手で持ち回すと「どれが最新か」が
分からなくなる。ステータス列を書き換えるのではなく、イベント（送信/返信/…）を
積み上げる形にしてあるので、集計は後から何度でもやり直せる。

**名寄せは分ける側に倒す。** チェーン店は全支店が同じドメインを持ち、
Wix や sites.google.com のような共有ドメインもある。ドメインだけで束ねると
別の店が1件に潰れて、それは後から復元できない。そこで住所（番地＋郵便番号）を
識別子に加えている。逆に統合漏れは、文面生成の時点でメールアドレス単位に
1通へ絞ることで吸収する。

**A/Bは文章を良くするためではなく測るためにある。** 枝は `lead_id` で機械的に
半々に割る（乱数ではないので、何度実行しても同じリードは同じ枝に入り、集計が
後から崩れない）。件数が足りないときは `stats` が「参考値」と明示するので、
差が出ていないのに出たことにする事故が起きない。

**再収集で既存データを壊さない。** upsert は空欄を埋める方向にだけ更新する。
手で入れたメールアドレスが再スクレイプで消えることはない。

## 相手先への配慮

- 全テンプレートに配信停止の一文が入る（GDPR対応であると同時に、迷惑メール判定を
  避けて到達率を守るため）。`jepra log unsubscribed --lead N` で以後の対象から外れる。
- サイト巡回は robots.txt に従い、1サイトあたり最大4ページ、リクエスト間に待ちを入れる。
- Overpass は共有インフラなので連続実行時に間隔を空ける。
- 同梱のデモデータに推測で作ったメールアドレスは含まれていない。

## 開発

```bash
python3 -m unittest discover -s tests    # 77 tests
```

```
src/jepra/
  cli.py          サブコマンド
  pipeline.py     収集→補完→文面生成
  store.py        SQLite（leads / events / drafts）
  models.py       Lead, Event, ステージ定義
  normalize.py    名寄せ（URL・電話・住所・店名）
  metrics.py      ファネル集計とA/B検定
  csvio.py        CSVの取り込みと書き出し
  simulate.py     計測レイヤ確認用の架空データ
  sources/        overpass / google_places / fixture
  enrich/         サイト巡回によるメール発掘
  outreach/       多言語テンプレート
```

新しい収集ソースは `sources/base.py` の `Source` を実装して
`sources/__init__.py` に登録するだけで `--source` に出る。
業種を足す場合は `sources/base.py` の `CATEGORIES` に1エントリ追加する。
