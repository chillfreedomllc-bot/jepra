# kirinuki

ゲーム実況の生素材から、**盛り上がっている場所を見つけて切り出す**ツール。

3時間の素材を目で追って「使える場面」を探す作業をなくすために作った。
出てくるのは短いmp4なので、そのまま CapCut にドラッグできる。

```bash
kirinuki scan 実況.mp4              # 候補を一覧するだけ
kirinuki cut  実況.mp4 --top 10     # 上位10本を切り出す
```

## 何を見て判断しているか

**その素材の普段の音量から、どれだけ跳ね上がったか**だけを見ている。
絶対的な音量で判定すると、録音レベルの違う素材ごとにしきい値を調整することになる。

スコアは3つの合計。

| 要素 | 意味 |
|---|---|
| 跳ね上がり | 普段の音量から何dB超えたか |
| 直前の静けさ | 直前5秒が静かなほど加点（上限あり） |
| 反応の長さ | 一瞬のノイズより、続いた反応を上に置く |

2番目がホラーゲーム向けの工夫。**悲鳴そのものより「静かに歩く→悲鳴」の落差**が
切り抜きとして成立するので、直前が静かだった場面を優先して拾う。

同じ理由で、切り出し範囲は**反応の8秒前から**始まる（`--pre-roll` で変更可）。
悲鳴の瞬間だけ切っても、見ている側には何が起きたか分からない。

## インストール

```bash
pip install -e .
```

Python 3.9 以上。依存は numpy と imageio-ffmpeg のみ。
ffmpeg が既に PATH にあればそちらが優先される。

## 使い方

### 候補を見る

```bash
kirinuki scan 実況_第12回.mp4
```

```
解析中: 実況_第12回.mp4（0:03:00.0）
  普段の音量: -23.0 dBFS / 反応を検出: 3箇所 → 切り抜き候補 3本

    #          開始          終了      長さ     スコア     反応
  ------------------------------------------------------
    1   0:02:22.0   0:02:35.0   13.0s    28.4      1
    2   0:00:37.0   0:00:50.5   13.5s    28.4      1
    3   0:01:32.0   0:01:46.0   14.0s    28.4      1
```

`--csv out.csv` を付ければ一覧をCSVに残せる。

### 切り出す

```bash
kirinuki cut 実況_第12回.mp4 --top 10           # 横型のまま
kirinuki cut 実況_第12回.mp4 --top 5 --vertical  # 9:16の縦型（ショート用）
```

`kirinuki_out/` に `実況_第12回_01.mp4` … が出る。CapCut にドラッグして使う。

縦型は既定で**ぼかし背景**（ゲーム画面を一切切らずに9:16へ収める）。
`--vertical-style crop` にすると中央だけを使うが、顔出しワイプがあると切れる。

### 候補が多すぎる / 少なすぎる

```bash
kirinuki scan 実況.mp4 --threshold 6    # 拾いやすくする（既定 8.0）
kirinuki scan 実況.mp4 --threshold 12   # 大きい反応だけに絞る
```

## PCへの負荷

| 工程 | 負荷 |
|---|---|
| `scan` | **軽い。** 3時間の素材で約16秒、メモリ35MB程度 |
| `cut` | 再エンコードするぶん重い。ただし切るのは短い区間だけ |

`scan` が軽いのは**映像をデコードしないから**。音声だけを16kHzモノラルに落として読む。
メモリも素材の長さに比例しない（区切って流している）。

`cut` は NVIDIA GPU があれば自動で使う（`h264_nvenc`）。CPU負荷はほとんど乗らない。

```bash
kirinuki cut 実況.mp4 --encoder cpu     # GPUを使わない
kirinuki cut 実況.mp4 --threads 2       # CPUを2スレッドに制限
```

他の作業と並行するなら `--threads 2` を付けると体感の重さが下がる。
**録画しながらの実行は避けたほうがいい**（ディスクの読み書きが競合する）。

## 字幕について

**このツールは字幕を作らない。** CapCut に自動字幕の機能があり、日本語も通るため。

精度が足りない場合は `faster-whisper` をローカルで回す方法があるが、
まず CapCut のものを試してからでいい。

## わかっている限界

- **判断材料は音だけ。** 静かな名場面（伏線・演出）は拾えない
- 音量が急に上がるものは何でも拾う。**BGMの盛り上がりや効果音も候補に入る**
- スコアはあくまで並び替えの目安。上位から順に中身を見て選ぶ前提

3時間から10箇所に絞る道具であって、10箇所から1箇所を選ぶのは人の仕事。

## 開発

```bash
python3 -m unittest discover -s tests    # 40 tests
```

テストは合成動画（`tests/make_fixture.py`）を実際に ffmpeg で作って通す。
BGMが鳴り続ける中に会話と悲鳴を置いた素材で、**悲鳴だけを誤検出ゼロで拾えるか**を
確認している。無音を背景にすると検出が簡単すぎて、テストとして意味を持たない。

```
kirinuki/
  analyze.py   音量の解析、盛り上がりの検出、切り出し範囲の決定
  extract.py   ffmpegでの切り出しと縦型変換
  ffmpeg.py    ffmpegの場所解決、逐次読み出し、エンコーダ選択
  cli.py       scan / cut
```
